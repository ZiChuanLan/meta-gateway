# 全站体验审查：界面、交互、动效与功能逻辑

基线：`experiment/availability` / `28913cfb4c04f2eb33d776bcb4452b9f3fbc8b19`。

方法：依用户要求，由主代理单上下文独立完成，不派子代理。源码、隔离实例与浏览器交互结合。本文是审查与建议，未修改业务实现；不把页面能打开等同于全部功能已验收。

## 0. 总结

**不是缺少一套新皮肤，而是页面的职责、状态和操作规则尚未统一。**

现代主题已有中性色、蓝色主操作、主从工作区与共享弹层，经典主题也有清晰身份。这些资产应保留。当前最值得投入的是：

1. 修正会算错钱、丢失编辑内容、误导操作方向的问题。
2. 按任务组织入口，减少同一对象分散在多个面板、同一词却代表不同东西。
3. 统一页面/详情/编辑器的空间规则、保存规则、状态文案与动作反馈。
4. 修移动端的布局拓扑，而非只是把桌面列堆起来。
5. 动效服务状态变化，不让日常工作反复等待演出。

价格架构详见 `pricing-architecture-review.md`。价格不是唯一审查范围，以下覆盖整个控制台。

## 2. 已确认的问题：先修逻辑，后修视觉

### U01 — P1：未保存 OAuth 输入离开后无提示丢失

实际步骤：OAuth 页填 `Client ID` → 点击全局“总览” → 返回 OAuth。没有确认，字段回到空。没有保存服务器设置。

证据：`web/src/team/OAuthPanel.tsx:30-49` 只有局部 draft；全局导航未拦截。`lib/unsavedChanges.ts:15-18` 明说没有路由 blocker，但其“sidebar 交给 browser prompt”注释不成立：SPA 内导航不会触发 beforeunload。

建议：建立共享的编辑离开契约，包含侧栏、命令面板、浏览器后退、tabs、关闭弹层；只对 dirty 表单拦截。运行参数即时保存失败也应保留草稿并阻止静默离开。并非所有点击都加确认。

### U02 — P1：成员空日志页提供无权访问的主动作

成员 `/logs` 空态显示“去通道”，实际访问 `/channels` 被重定向总览；直接请求 `/admin/sites` 返回 403。

证据：`web/src/features/Logs.tsx:944-955` 的空态动作无能力分支。安全边界有效，但 UI 带人走死路。

建议：共享展示必须接受 capabilities，不只换 API。成员空态提供“创建令牌 / 去工作台”；管理员可用“检查连接”。同样检查各页 empty/error/tooltip 的角色分支。

### U03 — P1：管理 API 限流被解释成上游限流

快速浏览触发 `/admin/channels/overview`、`/admin/downstream-keys` 等本机 429，界面却说“上游正在限流（429 / 408）”。这次是测试快速切页触发，**不推断普通访问一定频繁触发**。

证据：`web/src/i18n/zh.ts:260`；`web/src/errorCatalog.ts` 将 rate_limited 统一归类；`internal/httpapi/router.go:264-266` 管理端自身限流。

建议：错误结构含 origin（gateway_admin / gateway_relay / upstream / client），显示请求路径、Retry-After 和针对性动作；同一轮共享请求失败只给一个汇总错误，不用多个重复大错误卡压住内容。

### U04 — P1：移动模型目录只有约一行高

390px 下实测 `.list-shell-body` 高 123px、内容高 776px，6 条模型只能在很窄的内滚动区查看。截图 `mobile-a-3.jpg`。没有页面横向溢出，不代表可用。

证据：`web/src/styles/workspaces.css:195-196` 将目录 max-height 固定为 330px，头部、搜索、分页又消耗空间。

建议：手机改为“目录页 → 模型详情”的两步拓扑，回到列表恢复滚动与筛选；或折叠目录为模型切换器。不要把桌面 master/detail 原样上下叠加后压缩列表。

### U05 — P2：令牌安全文案互相矛盾

列表称明文可重新查看；创建提示及复制警告称“只显示一次、关闭后无法查看”；旋转又称可重新查看。

证据：`web/src/i18n/zh.ts:1283,2006,2014,2019,2025`，`internal/httpapi/admin_keys.go:176-187` 确实加密存储、默认启用。

建议：按返回的可恢复能力显示准确文案，不沿用一次性密钥模板。不能改成“明文落库”；真实行为是加密存储。

### U06 — P2：同步/接入文案与 manual 默认不一致

新增路由仍提示“同步模型会自动创建路由”。实际上 manual 模式只刷新候选，是否接入还要操作员采纳。

证据：`web/src/i18n/zh.ts:1490` 对比 `features/ChannelModels.tsx:523-577`。

建议：用“刷新模型清单 / 接入路由 / 停用成员 / 移除绑定”四个准确动作，按当前模式说明副作用，不把同步一词承包四种行为。

### U07 — P2：普通管理员仍是第三套简化壳

实际登录普通 admin 只见品牌、退出和用户管理两个板块；owner 和 member 走 ConsoleShell。没有现代导航、外观入口等。

证据：`web/src/App.tsx:238-247`、`web/src/team/StandaloneAdmin.tsx:7-28`，这是代码刻意行为，不是鉴权绕过。

建议：复用同一个 ConsoleShell，用角色能力过滤导航。统一外观不等于扩大管理权限；普通 admin 仍只能管理获授权的成员事项。

### U08 — P2：数据字号与信息堆叠不匹配

模型标识、状态 badge、可用性数字实测多处 11px，导航 12px。成员行把 ID、优先级、权重、价格来源、余额估算、失败和冷却塞进一行小字。

证据：`styles/workspaces.css:102-104`、`features/models/RouteMemberList.tsx:218-297`，浏览器 computed style 实测。

[INFERENCE] 大量重要事实与辅助事实同等弱化，会拖慢扫描并使长名称下操作变难；这是设计判断，不是 WCAG 自动判定失败。

建议：正文/主数据 14px 左右、辅助信息 12px 左右；金额/计数用 tabular-nums。减少首行 badge，重要状态独立列，其余按需展开。不只是全站字号整体放大。

### U09 — P2：观察页面的动词没有说清影响对象

“导入公开目录 / 立即采集 / 自动调整 / 采用价格”混在一处。前两项只读/配置源，自动调整会改路由可用性，采用价格会改计费。

证据：`SiteObservationWorkspace.tsx:214-229,337-360,573-579`。

建议：分为“采集数据”“路由保护”“报价”三块，明确“按观测调整路由”“复制为网关计费”。全局刷新与单站刷新名称区分；只读刷新不弹确认，改收费的动作给差异与目标对象。

### U10 — P2：失去作用域的状态容易被当成事实

总览有成功请求，但健康概况仍 0/3，因为健康扫描尚未产生数据。模型就绪与渠道健康不是同一指标。无报价/无余额/未检测都常以 `—` 或“暂无上游报价”合并。

建议：健康区拆“健康 / 异常 / 未检测 / 停用”；就绪明确是配置可路由，不是实测服务成功。所有时间窗口、样本数、来源、更新状态有稳定解释入口。

### U11 — 性能风险：每张成员模型卡单独请求参考价

`member/ModelsWorkspace.tsx:374-380` 每模型挂 `ModelPriceSummary`，后者一模型一请求；价格接口逐候选读本地价格。属于可观察结构，不声称已完成千模型压测。

建议：合并当前页批量报价接口/预取，只读本地快照；热点刷新与静态元数据分开。先做请求预算，再按测量决定虚拟列表，而不是先换前端框架。

### U12 — 需要进一步回归：运行参数自动保存与服务器冲突

`RuntimeSettingsPanel.tsx:456-473` 每次失焦发送完整 draft，队列只在当前页面内串行；远端变更可见后也不等于 PUT 有版本约束。

[INFERENCE] 两个管理员同时改不相关字段可能覆盖。需要真实版本冲突测试；本轮未复现，不以 bug 定案。推荐字段 patch + revision/CAS，而不是只靠查询刷新判断。

## 3. 保留已有正确设计

- 经典/现代的 token、共享弹层、菜单、列表基础设施继续用，不再做第三套控件。
- 手机上导航打开后选页自动关闭，已实测。
- 嵌套类型选择器：第一次 Escape 关闭 listbox，第二次关闭父 Dialog，已实测。
- Tab 在已测弹层内保持；明暗切换保留 OAuth 未保存输入，已实测。
- Ctrl+K 命令面板可开关；成员不请求管理员搜索。
- 文字工作台真实 mock SSE 完成与停止：停止后保留部分结果并显示“已停止”；图片 mock 能形成结果与历史。
- 管理 API 拒绝普通成员（403）；前端直达管理页会重定向，未发现本次操作中的越权。
- 减少动态效果有效：通过 DOM MutationObserver 测得普通入场 2104ms、reduce 165ms。早先工具调用总耗时含自动等待，**不能拿工具墙钟当动画时长**。

## 4. 全局交互模型：先统一规则

### 4.1 导航按工作对象，不按技术模块堆入口

保留大体位置，逐步把现有入口归为：

- **工作空间**：总览、连接、模型、令牌。
- **请求与观测**：工作台、日志（代理/实时/发现/审计）。站点观测仍从连接进入，不新添重复顶栏快捷入口。
- **管理**：用户、签到、交换/备份入口、拓展、设置。

“连接/站点/账号/Key/渠道”首次出现时解释映射，但不要每行重复教材。深链接保存对象、tab、分组、筛选；返回时保留列表滚动。重定向应指出权限或旧地址原因，不让人感觉操作没发生。

权限只控制可见动作和数据，不产生三套外壳。同一功能只有一个规范编辑位置，其他地方展示摘要并链接过去。

### 4.2 面板规则

| 容器 | 适用任务 | 不该装什么 |
|---|---|---|
| 整页 | 长列表、跨对象比较、长设置、可分享的深链接 | 一层层卡片和重复页标题 |
| 主从详情 | 桌面选择一个对象后持续查看/操作 | 和主表并排争抢宽度的第二张全量表 |
| Drawer | 对单个对象修改，保留列表上下文 | 导入/定价/授权等超长完整工作台 |
| Dialog | 短任务、差异确认、少字段编辑 | 需要多个滚动层的长表单 |
| Popover/menu | 少量即时动作、辅助解释 | 重要错误或唯一的功能说明 |

建议桌面只有一个主内容滚动域，目录需要内滚时给足至少数行可见空间；手机详情全屏呈现，返回不丢选择。避免页面滚动 + 卡片滚动 + Dialog body 滚动同时出现。

### 4.3 操作规则

- 每页一个最主要动作；其余放明确分组的“更多”，不让四个同权重按钮争第一眼。
- 列表行显示高频动作，其余菜单；右键与按钮菜单同源。
- 切换开关：即时生效就明确写“已生效/保存中/失败可重试”；需要整体保存的表单显示 dirty 及固定保存条。
- 只读刷新、查看不确认；删除/覆盖/改价按影响提供一次清楚的确认。不是到处加弹窗。
- 批量操作明确“已选 N 条 / 当前筛选 M 条 / 全部”，执行结果逐项计数；全失败不能显示“操作成功”。
- 未知、未配置、明确 0、空结果、加载、刷新失败保留旧值各有独立状态。
- 修改规则时展示“影响未来请求/影响哪些对象”，不重算历史，不因 UI 重新读取而发付费探测。

## 5. 逐页重组建议

以下为设计建议，非声称当前全部存在 bug。

### 登录与首次使用

保留品牌表达，但日常登录只需要短过渡。长入场适合首次或手动重播。把账号认领、个人/团队选择、连接、模型、令牌接成一个清楚的首登路径；避免刚完成登录又被设置向导、账号弹窗、12 步导览连续截断。

“旧版本升级”和“更多登录方式”按可用性出现，错误落在当前字段/当前方式。真实访客应能立即看清当前站点、正在登录谁、失败后如何恢复。

### 总览

首屏回答“是否需要处理、调用是否正常、钱花在哪里”。固定结构：

1. 少量关键读数 + 窗口；
2. 待处理事项（无可用渠道、待确认价格、刷新失败）；
3. 主要趋势；
4. 最近请求/模型排行。

API Base URL 可以是紧凑工具条，不抢占比监控还大的视觉面积。空公告不长期占半块面板；已停用与未检测不混进异常分母。

### 连接与渠道模型

连接目录重点是名称/站点、可调用状态、模型覆盖、凭证状态和最近检查。优先级权重进详情，不是主表第一层。

连接详情按“概览 / 模型 / 凭证 / 余额与报价 / 高级”组织；复用现有能力，不要求立即新增独立导航。明确账户凭据用于余额/签到，API Key 用于中继。

渠道模型页面默认展开有效或搜索命中的组，折叠全组时提供“展开全部”。“接入”“停用”“移除绑定”分开，自动/手动模式切换显示后续影响。

### 模型工作区

桌面窄目录 + 宽详情可保留，但目录至少可扫到多条模型。详情先显示“当前路由状态、所在组、真正可能承接的候选”，然后路由策略，再成员列表。

推荐详情采用“路由 / 计费 / 能力”任务切换。能力元数据编辑不夹杂收费；每模型倍率不让用户绕到用户管理的“计价”。

成员列表把优先级/权重作为配置，把实测健康作为观测，把有效价格作为结算解释，三者不能混成一串小字。手机进入详情后给“返回模型目录”和模型切换器。

### 价格与余额面板

- 站点：“原生余额 / 上游报价 / 来源与单位”。
- 模型：“本网关怎么记账 / 默认规则 / 成员覆盖 / 测算”。
- 参考目录：明确“参考，不代表本站实际扣费”。
- 日志：金额点击展开所用规则和用量来源。
- 用 /1M 统一人可读编辑与显示；后端旧 /1k 可由边界换算，不为了 UI 迁整库。

### 令牌与成员额度

区分原始上游 Key、下游调用令牌、登录会话。名称下面可显示用途/拥有者，但不要让所有密钥都叫“令牌”而无主体。

额度列同时保留 token 和金额，分别显示无限/用尽/未知，不用一个百分比代替两种约束。显式创建/旋转/恢复明文说明一致。高级模型白名单/IP/有效期渐进展开。

### 工作台

请求配置和结果应共享顶部对齐；长结果是主角，不被固定大空卡框住。保留图像/文字两种任务；模型选择下方显示实际能力与有效端点。

提供一个明确发送/生成动作、就近停止。忙碌时不要全页都不可用；只锁定影响本请求的字段。完成、已停止、上游失败、解析失败分别反馈。上游指定不可用时不能看起来像一个正常可选项。

### 日志与实时轨迹

代理日志默认保留时间、模型、结果、耗时、费用；路径、Key 指纹、每次 attempt、缓存明细在展开详情。手机用摘要行 + 展开，不靠横向拖动十二列找关键信息。

筛选需要可见的生效状态、清空入口与深链接；图表与表格窗口应明确一致或明确说明不同。失败、慢请求、缓存命中不靠颜色单独表达。

实时轨迹区别“连接中 / 已连接但暂无请求 / 暂停 / 断线重连”。“全部中止”是有副作用的操作，与暂停显示不同。成员空态提供有权限的下一步。

### 签到与保活

不是同一个定时任务。签到是账户活动，保活是避免空闲封禁的真实调用；表头/按钮明确是否耗 token。

签到页按“下次执行 / 需要处理 / 结果”组织；状态筛选翻译 success/failed/skipped。外部 Cookie 站点用独立标识，但配置与结果采用一致行结构。

保活显示账户级空闲窗口、选用模型、为什么跳过、下一次决策，不把无可用模型的发送按钮做成貌似可用。

### 交换、备份与恢复

当前 WebDAV 两块长表单把“导入资产”和“上传备份”放在同一层，手机需要很长滚动才到本地文件导入。

建议先选任务“导入 / 导出 / 云同步”，再配置该任务；不是要求用户理解两套底层协议。增量/覆盖的影响范围在操作旁，危险覆盖给一次预览。

备份说明对象边界（数据库全量 vs 交换包渠道资产），离线恢复说明不是一个伪“恢复”按钮。配置/凭据不因浏览器刷新丢草稿。

### 用户管理

保留成员、策略、额度的实体边界，但使用同一工作区标题和可扫的局部导航。8 个入口手机不应变成两行难辨的小链接；使用当前分区选择器或横向可滚且显露溢出的 tabs。

成员行显示角色、状态、策略、额度。策略说明“模型权限”与“允许的上游候选”同时约束，而不是只展示计数。

“计价”从用户管理中拆回模型计费职责；用户管理额度页只管理谁能用多少，不重复定价编辑器。

普通管理员复用统一外壳且只见成员事项。模式总开关对其只读展示，避免大段危险说明占据无权操作的首页。

### 设置

保持“运行参数 / 外观 / 备份 / 账号”定位，但运行参数分区不应全靠一长排小锚点。

桌面左索引 + 右侧单列配置，每分区一条清楚说明、来源和保存状态；手机用分区选择器，减少进入第一字段前的标签墙。外观、路由、网络等不能使用不同的保存习惯而毫无提示。

网络/调度字段展示实际生效值与继承来源；0 表示跟随默认时在控件旁显式说明。原始 JSON 只作为高级入口，常用告警规则给结构化编辑。

危险操作独立区，显示备份前提和范围；“恢复分区默认”可撤销或在表单草稿中完成，避免一个不显眼按钮直接改变整区运行行为。

### 拓展与插件

保留插件注册、市场、已安装三项。已安装为空时不要空面板先占整屏；注册是当前主任务就靠前。市场失败显示可重试和使用已有安装，不一直无期限“加载中”。

显示来源、权限、健康、启用状态、版本；iframe 加载失败有返回和诊断入口。平台提供容器/权限边界，不让插件私改宿主导航和样式。

### 个人设置

把额度/兑换、调用偏好、安全会话、外观分别分节。只有可修改偏好才出现保存；只读站点默认与实际生效并排解释。

账号名和额度不必重复两遍；“修改密码并退出所有会话”明确是否包含当前会话。手机上保留安全动作大触摸区。

## 6. 视觉系统建议

### 排版与密度

- 现代主题继续纸白/石墨 + 蓝色，不另加渐变、玻璃和装饰大卡片。
- 页面标题 24–28px、分区 16–18px、主要内容约 14px、辅助信息约 12px；必要标识可等宽，正文不用全等宽。最终按实际字体测量，不把数值当一次性全局替换命令。
- 数字右对齐、tabular-nums；金额单位留在列头/旁注，未知用语义文字，不让 `—` 代替所有状态。
- 行内间距 8/12/16、区块 24/32。先合并重复容器，再调间距。
- 舒适/紧凑密度改变行高与间距，不压小关键字号。
- 内容层用稳定背景，悬浮层才用阴影；主操作有色、普通操作低权重、危险操作仅在真正危险时红。
- 经典主题保持蓝金和结构感，但复用相同内容层次与可访问性标准，不用维护一套独立业务页。

### 组件维护

`styles.css`、classic theme 与后加 CSS 有多轮覆盖，主题内特殊选择器可能抵消共享组件规则。不要做全仓 CSS 重写。先提取明确的 PageHeader、EntityList、DetailPanel、EditorFooter、StatusReadout、OperationResult 契约，改到哪个组件就删除其重复覆盖并验收两主题。

## 7. 动效建议

| 场景 | 建议 | 原则 |
|---|---|---|
| 登录/品牌 | 首次或主动重播保留完整表现，日常短过渡 | 不阻塞认证与数据加载，不每次都等两秒 |
| 切页 | 轻量 120–180ms 透明度/小位移 | 不给整个工作区重复扫光，避免长表抖动 |
| Drawer/Dialog | 约 160–220ms，退场更短 | 焦点与滚动锁跟状态，不等视觉结束才安全 |
| 明暗/主题 | 约 180–250ms 或短交叉淡入 | 大斜切 520ms 可作为可选风格，不强制日常操作 |
| 数字 | 首次加载直接显示真实值；变化用轻微强调 | 不从 0 滚数把“有数据”暂时表现成“没有” |
| 实时状态 | 仅正在运行/需要注意时有动作 | 健康灯常亮即可，不让所有好状态一直呼吸 |
| 结果/错误 | 变化处短促确认，保留历史 | 不因全页刷新重播所有行 |
| reduce/隐藏页面 | 去掉装饰，隐藏后暂停循环 | 计费/网络/取消生命周期不得靠动画定时器 |

现有减少动态效果、Escape、隐藏页面 canvas 处理应保留。没有实测帧率、低端设备 CPU 或隐藏页全 CSS 动画暂停，不声称这几项已过。

## 8. 性能与“快”的设计

- 冷页面读本地快照，不让浏览模型等待逐渠道余额/报价抓取。后台刷新保留最后成功数据并标新鲜度。
- Shell 查询与页内相同实体共享 query key；进入页面不重复拉同一份权限、配置和渠道统计。
- 只轮询真变化数据；离开页面/隐藏标签后停不必要刷新。并行请求应有批量接口和预算，避免自己撞管理限流。
- 当前临时 Vite build 的主 `index` 929.14kB（gzip 294.06kB）并有 >500kB warning。先定位静态依赖，再按主题/重组件/规则编辑器拆分；不要靠调高 warning 阈值“优化”。
- 首屏不等低优先级公告、目录、市场或财务。失败不连带主列表归零。
- 不为 6 行列表上虚拟化；在 100/1000 模型真实测量后选分页/虚拟化。

## 9. 分阶段实施顺序

### 第一批：正确性与信任

六个价格复现缺陷；成员错误 CTA；OAuth/长表单离开保护；本地/上游错误归因；密钥/同步文案。对每条先保留复现再修，不先做皮肤。

### 第二批：统一结构和状态

共享角色壳层、保存契约、对象页/详情/编辑器规则、移动模型目录拓扑、明确未知/空/失败/免费。价源与计费分离 API 接到新面板。

### 第三批：逐工作区整理

连接/模型/令牌 → 日志/工作台 → 用户管理 → 设置/签到/交换/拓展。每批保留原深链接与权限，避免“大改版”同时移动全部入口。

### 第四批：视觉和动效精修

字体与行高、表格对齐、颜色语义、移动触摸区、动画节奏、包体与请求预算。使用同一真实样本在两主题验收，不用全空 demo 冒充功能完成。

### 每批验收

- 角色：部署管理员、owner、admin、member 的可见与可操作集合。
- 视口：桌面、窄桌面、390px；测试超长中英文、0/1/1000 条、200% 放大。
- 状态：加载、空、筛选空、刷新失败保留旧值、401/403/429、部分批量成功、保存冲突。
- 交互：键盘、IME Escape、嵌套层、焦点恢复、未保存导航、重复点击、取消与切页。
- 动效：普通/reduce、隐藏/恢复、切主题保留输入、渲染期间不伪造 0 状态。
- 数据：页面读不改配置、不触发付费探测；复制报价不意外变价；日志金额能解释。
